# Fork: open-seo-vertion

Fork of https://github.com/every-app/open-seo with one addition: a native
Bing Webmaster Tools integration. Everything else follows upstream.

## What the fork adds

- Bing API key per project (Settings → Integrations → "Bing Webmaster Tools"),
  stored encrypted with `BETTER_AUTH_SECRET` (`better-auth/crypto`), never sent
  to the client.
- Dashboard card "Bing", page "Bing Insights" under My Site
  (`/p/$projectId/bing`), MCP tool `get_bing_performance` (read only, no
  credits), `bing` entry in `/api/health`.
- Image workflow `.github/workflows/fork-image.yml`: builds the standalone
  image as `ghcr.io/<owner>/open-seo-standalone` on push to `main`.

Fork-only files (no upstream conflicts):

- `src/server/lib/bingClient.ts`
- `src/server/features/bing/*`
- `src/serverFunctions/bing.ts`
- `src/server/mcp/tools/get-bing-performance.ts`
- `src/client/features/bing/*`
- `src/routes/_app/p/$projectId/bing.tsx`
- `drizzle/sqlite/9000_fork_bing_connections.sql`
- `.github/workflows/fork-image.yml`, `FORK.md`

Small edits in upstream files (where merge conflicts can appear):

- `src/db/gsc.schema.ts`, `src/db/pg/gsc.schema.ts`: `bingConnections` appended
- `src/db/schema.ts`: `bingConnections` in the export list
- `src/server/mcp/server.ts`: import + `register(getBingPerformanceTool)`
- `src/server/lib/setup-status.ts`: `checkBing()`
- `src/client/navigation/items.ts`, `src/client/features/dashboard/DashboardPage.tsx`,
  `src/routes/_app/p/$projectId/settings/integrations.tsx`: one entry each
- `src/routeTree.gen.ts`: regenerated by the build
- `src/server/everyapp/tools.test.ts`: tool count +1

## Migration

The SQLite migration is hand-written and numbered `9000_…` so it never
collides with an upstream name. D1/celld apply every file not yet applied, so
later upstream migrations (`0069_…`) still run. It is not in drizzle's
`meta/_journal.json`; do not run `pnpm db:generate` in the fork without
removing the Bing table from the diff afterwards. No Postgres migration: the
self-hosted standalone edition uses SQLite only.

If an upstream migration ever rebuilds `projects` (DROP TABLE), the cascade
deletes `bing_connections` rows: re-enter the key.

## Merging upstream

```bash
git remote add upstream https://github.com/every-app/open-seo.git  # once
git fetch upstream --tags
git merge upstream/main          # or a release tag, e.g. v0.1.28
# conflicts: keep both sides; for src/routeTree.gen.ts take upstream, then build
npx -y pnpm@10.30.1 install
npx -y pnpm@10.30.1 build && npx -y pnpm@10.30.1 lint && npx -y pnpm@10.30.1 test
git push                         # fork-image.yml publishes the new image
```

## Deploy (Proxmox CT 122, /opt/open-seo)

The standalone compose pulls `${OPENSEO_IMAGE}`. Set in `/opt/open-seo/.env`
(compose reads it from the directory):

```
OPENSEO_IMAGE=ghcr.io/dxnielhrf/open-seo-standalone:latest
```

then `docker compose pull && docker compose up -d`. The `init` service applies
migrations. Back out by removing the line (upstream image ignores the extra
table).
