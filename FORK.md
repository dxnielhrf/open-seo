# Fork: open-seo-vertion

Fork of https://github.com/every-app/open-seo with three additions: native
Bing Webmaster Tools and Microsoft Clarity integrations, and a report of all
GA4 events (not only key events). Everything else follows upstream.

## What the fork adds

- Bing API key per project (Settings → Integrations → "Bing Webmaster Tools"),
  stored encrypted with `BETTER_AUTH_SECRET` (`better-auth/crypto`), never sent
  to the client.
- Dashboard card "Bing", page "Bing Insights" under My Site
  (`/p/$projectId/bing`), MCP tools `get_bing_performance` and
  `get_bing_backlinks` (read only, no credits), `bing` entry in `/api/health`.
- Image workflow `.github/workflows/fork-image.yml`: builds the standalone
  image as `ghcr.io/<owner>/open-seo-standalone` on push to `main`.

- Microsoft Clarity Data Export token per project (Settings → Integrations →
  "Microsoft Clarity"), encrypted the same way. Clarity's API only serves the
  last 1-3 days with 10 requests per project per day, so the daily cron
  (`17 3 * * *`, `src/server.ts` `scheduled`) stores a snapshot of the last
  24 h in `clarity_snapshots`: totals plus URL, Source and Device breakdowns
  (4 requests). Connecting takes the first snapshot at once (another 4).
  Dashboard card "Clarity", page "Clarity Insights" (`/p/$projectId/clarity`),
  MCP tool `get_clarity_insights` (reads stored snapshots only), `clarity`
  entry in `/api/health`.
- GA4 report kind `events` (eventCount, totalUsers for every event; breakdown
  by event, page path, `customEvent:<param>` or session source/medium; filter
  by event names; all channels by default). MCP tool
  `get_google_analytics_events`, dashboard card "GA4 events", page
  "GA4 Events" (`/p/$projectId/ga4-events`). Parameters must be registered in
  GA4 as event-scoped custom dimensions.

## Migration

The SQLite migrations are hand-written and numbered `9000_…`, `9001_…` so it never
collides with an upstream name. D1/celld apply every file not yet applied, so
later upstream migrations (`0069_…`) still run. It is not in drizzle's
`meta/_journal.json`; do not run `pnpm db:generate` in the fork without
removing the fork tables from the diff afterwards. No Postgres migration: the
self-hosted standalone edition uses SQLite only.

If an upstream migration ever rebuilds `projects` (DROP TABLE), the cascade
deletes `bing_connections`/`clarity_*` rows: re-enter the keys (Clarity
history older than 3 days is then lost).

## Merging upstream

```bash
git remote add upstream https://github.com/every-app/open-seo.git  # once
git fetch upstream --tags
git merge upstream/main          # or a release tag, e.g. v0.1.28
# conflicts: keep both sides; for src/routeTree.gen.ts take upstream, then build
npx -y pnpm@10.30.1 install
npx -y pnpm@10.30.1 build && npx -y pnpm@10.30.1 lint && npx -y pnpm@10.30.1 test
git push                         # fork-image.yml publishes the new image
```

## Deploy (Proxmox CT 122, /opt/open-seo)

The standalone compose pulls `${OPENSEO_IMAGE}`. Set in `/opt/open-seo/.env`
(compose reads it from the directory):

```
OPENSEO_IMAGE=ghcr.io/dxnielhrf/open-seo-standalone:latest
```

then, in `/opt/open-seo/deploy/standalone`:

```bash
docker compose -f compose.yaml -f compose.lan.yaml pull runtime
docker compose -f compose.yaml -f compose.lan.yaml up -d
```

`compose.lan.yaml` (local, untracked) publishes the web port on the LAN for
the Cloudflare tunnel in CT 100. Without it, web binds to 127.0.0.1 only and
seo.harfert.org answers 502. The `init` service applies
migrations. Back out by removing the line (upstream image ignores the extra
table).
